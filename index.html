Process Customization

SAP Cloud ALM Features provide standard change and deployment execution, but are not a one-to-one replacement for ChaRM. For additional change types, custom statuses, approval paths and differentiated workflows, we design governance in ServiceNow, Jira or Azure DevOps and integrate it with Cloud ALM Features and deployment status.

Workshop-scoped

Change & deployment

  • Map ChaRM change types (normal, urgent, administrative, defect) to Cloud ALM Features and external workflow records
  • Additional approval chains, custom statuses and segregation of duties in ServiceNow, Jira or Azure DevOps where needed
  • Connect external governance approvals to Cloud ALM feature and deployment gates using supported APIs
  • Define field mapping, status ownership, release calendar and freeze periods across both tools

Automation

  • Approval orchestration in external workflow tools or SAP Build Process Automation when technically appropriate
  • Email and Teams notifications on status changes
  • Role-based entry points in SAP Build Work Zone
  • Mass operations through the Cloud ALM APIs

Governance

  • Change KPIs: lead time, failure rate, gate violations
  • CAB and audit dashboards
  • Audit evidence pack: who approved what, and when
  • Scope set in 3–5 workshops: keep, simplify or drop each flow

Product 01 · CALM2Signavio

From SAP Cloud ALM to Signavio: bring your process content into your design hub.

SAP's standard BPMN integration synchronizes process diagrams from Signavio to Cloud ALM. CALM2Signavio addresses the complementary direction: inventory, map and transfer eligible process hierarchies and custom diagrams from Cloud ALM into Signavio, with controlled synchronization and process ownership. Exact coverage is validated against the APIs and BPMN data available in your tenant.

SOURCESAP Cloud ALMHierarchy · custom processes · BPMN · metadata
→CALM2Signavio
Mapping · diff · validation
TARGETSAP SignavioFolders · diagrams · attributes · governance
SAP standard: Signavio → Cloud ALM (BPMN)   |   CALM2Signavio offering: Cloud ALM → Signavio (assessed scope)

How it works

01 · Discover

Inventory & coverage

Read Cloud ALM process hierarchy, custom processes, diagram availability and external references. Flag missing BPMN, duplicate IDs and unsupported content before any change.

02 · Map

Preview target structure

Translate eligible hierarchy and process metadata into Signavio folders, attributes and diagrams. Produce a dry-run mapping for review.

03 · Transfer

Controlled initial load

Create approved target content through the supported Signavio interfaces, preserving traceability with source references and import logs.

04 · Reconcile

Delta & governance

Detect changes, respect the designated owner and flag conflicts. No automatic overwriting of independently edited diagrams; changes require explicit approval.

Operating modes

  • Migration: one-time bulk onboarding from Cloud ALM to Signavio
  • Transition: periodic delta review during handover of process authorship
  • Signavio-led: after handover, SAP standard Signavio → Cloud ALM sync remains the primary diagram flow

Technical scope & prerequisites

  • Cloud ALM API service access and permission to read the process model
  • Signavio API access and target workspace/folder design
  • BPMN availability check: legacy or SVG-only content may require remediation
  • Dry run, ownership rules, reconciliation report and scoped deployment

Delivery note: This describes the intended solution workflow, not a claim that all use cases are already deployed. API coverage, BPMN portability, Signavio licensing and conflict handling are validated during discovery.

Product 02 · SharePoint DMS for Cloud ALM

Link your Cloud ALM documentation with the Microsoft 365 ecosystem.

A governed integration approach for keeping documents in SharePoint while making them discoverable and traceable from SAP Cloud ALM. The supported architecture uses SAP Cloud ALM Document API references and mappings; it does not replace the SAP-managed BTP Document Management Service repository.

SAP SIDESAP Cloud ALMDocument records · URL references · project & process assignments
↔Integration service
Microsoft Graph + Cloud ALM Document API
MICROSOFT SIDESharePoint OnlineFiles · folders · versions · Microsoft 365 permissions

How it works

01 · Connect

Configure access

Authorize a SharePoint site through Microsoft Entra ID and connect the integration service to Cloud ALM APIs using least-privilege credentials.

02 · Map

Define document rules

Map SharePoint folder structure and file metadata to Cloud ALM projects, process hierarchy and document types. Validate the rules in a dry run.

03 · Reference

Publish linked records

For eligible SharePoint files, create Cloud ALM document records with URL references and process/project assignments, without relocating the original binary.

04 · Reconcile

Keep links current

Scheduled checks identify renamed, moved or deleted files. Handle link changes and deletions according to agreed rules and supported API operations.

Flow A · SharePoint → Cloud ALM

  • Files remain in Microsoft 365 under existing permissions and retention policies
  • Cloud ALM receives document entries and SharePoint URL references
  • Mapping and reconciliation preserve traceability to the source file

Flow B · Cloud ALM → SharePoint

  • Review Cloud ALM metadata and document references for reporting or linked-document workflows
  • Any binary extraction or file synchronization requires separate API and licensing validation
  • Cloud ALM native uploads continue using its SAP-managed DMS repository

Important boundary: SAP currently does not support using an arbitrary external SharePoint repository as a direct replacement for Cloud ALM's automatically created SAP BTP DMS repository. This offering targets supported document linking and integration patterns. Scope is subject to technical discovery.
