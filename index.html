Process Customization

Cloud ALM's standard flows rarely match a ChaRM setup one to one. We tailor Cloud ALM so the change process your teams know survives the move, with configuration first and SAP BTP only where configuration ends.

Workshop-scoped
What we tailor

Change & deployment

  • Feature workflows mirroring your ChaRM cycles (normal, urgent, admin, defect)
  • Approval steps, approver groups, segregation of duties
  • Quality gates and transport policies per release
  • Custom fields, templates, release calendar, freeze periods

Automation

  • Approval automation with SAP Build Process Automation
  • Email and Teams notifications on status changes
  • Role-based entry points in SAP Build Work Zone
  • Mass operations through the Cloud ALM APIs

Governance

  • Change KPIs: lead time, failure rate, gate violations
  • CAB and audit dashboards
  • Audit evidence pack: who approved what, and when
  • Scope set in 3–5 workshops: keep, simplify or drop each flow

Product · CALM2Signavio

One process model in SAP Cloud ALM and SAP Signavio.

CALM2Signavio loads your Cloud ALM process content into Signavio in bulk, then keeps both sides in sync with an approval step for every design change. It fills the direction SAP's standard integration does not cover.

Bulk load with a dry run first

Hierarchy becomes folders, each solution process becomes a BPMN diagram with its original element IDs. You see what will be created, what has no BPMN and what is invalid before anything is written.

Nothing overwritten without approval

Design changes go through Signavio Process Governance. Conflicts become change requests with a three-way diff. Deletions are never automatic.

Built on public APIs

Cloud ALM Process Hierarchy, Custom Processes and Process Management APIs; Signavio Process Manager API. Runs on SAP BTP or your own cloud, with a full audit log.

Mode A · defaultSignavio leads

After the bulk load, diagrams are edited in Signavio only. Cloud ALM receives approved changes.

Mode B · transitionCloud ALM leads

For projects still documenting in Cloud ALM. Changes flow to Signavio until handover.

Mode C · link-onlyReference, no copy

For SAP Best Practices content already in Signavio Process Explorer. Attributes and links only.

Typical rollout · 4–6 weeks

  1. Inventory and dry run: process list, BPMN coverage, proposed folder tree
  2. Initial load with folders, diagrams and attributes
  3. Delta runs and continuous sync
  4. Quality report: invalid BPMN, diagrams without BPMN, duplicates

What you need

  • Cloud ALM API access (OAuth client credentials)
  • Signavio technical user with API Edition
  • Signavio Process Governance for the approval flow
  • Fits customers coming from SolMan's Signavio connector, which has no Cloud ALM successor
