How it works ↓
Product 02 · SharePoint DMS for Cloud ALM

Link your Cloud ALM documentation with the Microsoft 365 ecosystem.

A governed integration approach for keeping documents in SharePoint while making them discoverable and traceable from SAP Cloud ALM. The supported architecture uses SAP Cloud ALM Document API references and mappings; it does not replace the SAP-managed BTP Document Management Service repository.

How it works

01 · Connect

Configure access

Authorize a SharePoint site through Microsoft Entra ID and connect the integration service to Cloud ALM APIs using least-privilege credentials.

02 · Map

Define document rules

Map SharePoint folder structure and file metadata to Cloud ALM projects, process hierarchy and document types. Validate the rules in a dry run.

03 · Reference

Publish linked records

For eligible SharePoint files, create Cloud ALM document records with URL references and process/project assignments, without relocating the original binary.

04 · Reconcile

Keep links current

Scheduled checks identify renamed, moved or deleted files. Handle link changes and deletions according to agreed rules and supported API operations.

Flow A · SharePoint → Cloud ALM

  • Files remain in Microsoft 365 under existing permissions and retention policies
  • Cloud ALM receives document entries and SharePoint URL references
  • Mapping and reconciliation preserve traceability to the source file

Flow B · Cloud ALM → SharePoint

  • Review Cloud ALM metadata and document references for reporting or linked-document workflows
  • Any binary extraction or file synchronization requires separate API and licensing validation
  • Cloud ALM native uploads continue using its SAP-managed DMS repository

Important boundary: SAP currently does not support using an arbitrary external SharePoint repository as a direct replacement for Cloud ALM's automatically created SAP BTP DMS repository. This offering targets supported document linking and integration patterns. Scope is subject to technical discovery.
