03
Extended scope

Process Customization

SAP Cloud ALM Features provide standard change and deployment execution, but are not a one-to-one replacement for ChaRM. For additional change types, custom statuses, approval paths and differentiated workflows, we design governance in ServiceNow, Jira or Azure DevOps and integrate it with Cloud ALM Features and deployment status.

Workshop-scoped
What we tailor

Change & deployment

  • Map ChaRM change types (normal, urgent, administrative, defect) to Cloud ALM Features and external workflow records
  • Additional approval chains, custom statuses and segregation of duties in ServiceNow, Jira or Azure DevOps where needed
  • Connect external governance approvals to Cloud ALM feature and deployment gates using supported APIs
  • Define field mapping, status ownership, release calendar and freeze periods across both tools

Automation

  • Approval orchestration in external workflow tools or SAP Build Process Automation when technically appropriate
  • Email and Teams notifications on status changes
  • Role-based entry points in SAP Build Work Zone
  • Mass operations through the Cloud ALM APIs

Governance

  • Change KPIs: lead time, failure rate, gate violations
  • CAB and audit dashboards
  • Audit evidence pack: who approved what, and when
  • Scope set in 3–5 workshops: keep, simplify or drop each flow

Tool Integrations

For teams whose change or ITSM process lives outside SAP. SAP Cloud ALM Features manage SAP-side change and deployment execution. ServiceNow, Jira or Azure DevOps can manage richer change types, statuses and approval processes, with agreed status mapping and integration between tools.
